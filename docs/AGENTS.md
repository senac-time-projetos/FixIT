# Instruções para documentação e specs

Estas regras complementam o `AGENTS.md` da raiz para arquivos em `docs/`.

- Escreva em português claro e mantenha identificadores técnicos estáveis.
- Separe requisito aprovado, proposta, hipótese e trabalho futuro.
- Não transforme data planejada em evidência de entrega.
- Não marque validação, teste ou aprovação como concluído sem fonte verificável.
- Specs são contratos vivos: atualize decisões e descobertas no mesmo PR que
  altera o comportamento.
- Evite duplicar requisitos. O documento específico deve apontar para a fonte
  canônica e acrescentar apenas o detalhe de sua área.
- Links de Figma devem incluir `node-id` quando uma tela for normativa.
- Ao concluir uma tarefa, atualize o estado real sem apagar histórico relevante.
